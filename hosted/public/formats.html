Every file type, and what you get

Oopsware reads a lot of file types. How much it can tell you depends on where you open the file. Here is the honest version: what happens right here in your browser, what the free desktop tool adds, what needs a separate tool you install yourself, and what is still on the way.

Nothing matches that. Clear the search or pick a different filter.

Here, in your browser

When you upload to the library, inspection runs on a plain Linux server with nothing extra installed, and your file is never run. Here is what that gives you.

Zip packages & app bundles

In your browser

.zip · .ipa · .apk · .appx · .msix · .jar · .aab

Every file inside is listed, hashed, and identified by its bytes, then unpacked so you can browse and download each one.

Built in. Nested archives aren't opened again; encrypted entries are named, not unpacked.

Electron archives

In your browser

.asar

Unpacks the files that make up an Electron desktop app so you can read and download them.

Built in.

Tar archives & gzip

In your browser

.tar · .tar.gz · .tgz · .gz

Recognized by their bytes, then every file inside is listed, hashed, and unpacked. A .gz that holds one file shows that file.

Built in. Links are listed, not created. Archives with duplicate names, sparse files, or devices are not unpacked, and the reason is shown.

Markdown & text

In your browser

.md · .markdown · .txt

Markdown is shown formatted, a whole block at a time, with raw HTML and scripts kept as plain text, unsafe links left unclickable, and remote images never loaded. Text keeps its exact lines and newlines and names any bytes that could not be decoded. A structure view and the raw bytes are one tab away.

Built in. Text originals up to 16 MiB, Markdown up to 4 MiB.

Data & config files

In your browser

.json · .jsonl · .yaml · .yml · .toml · .xml · .csv · .tsv

Parsed into a structure view where each value shows its path and its line and column in the file. Problems are listed with their exact place: a bad JSON Lines record or CSV row is named while the good ones stay readable, duplicate keys are flagged, and big numbers keep every digit. YAML aliases are never expanded, XML entities and DTDs are never loaded, and CSV formulas are shown only as text. TOML values are listed without line numbers.

Built in. JSON, JSON Lines, CSV and TSV originals up to 16 MiB; YAML, TOML and XML up to 4 MiB; the first 100,000 parts are browsable. A file too complex to read within the service’s memory budget, and files inside archives, keep the text view.

WebAssembly

In your browser

.wasm

Decoded without ever running it: imports, exports, memory and data, every section with its byte range, and each function with its signature, the functions it calls and its indirect calls. A text rendering (.wat) is a separate, clearly labelled download. Names come only from the module itself. SIMD, exception handling, GC and other newer proposals are named, not decoded; components are recognized only.

Built in. Modules up to 32 MiB; the first 20,000 functions are browsable. The desktop tool also reads .wat files and shows each function’s instructions and likely indirect-call targets.

Any other file

In your browser

everything else — programs, documents, images, data…

Identified by its bytes, with size and SHA-256, plus a paged text, hex, and printable-strings view. The original is always downloadable.

Built in. Taking a program apart (below) needs the desktop tool or a provider.

With the desktop tool (free, nothing extra)

Oopsware also runs on your own computer as a command and an agent tool. These work with nothing installed beyond Oopsware itself.

JavaScript & Electron apps

Desktop tool

a folder or .asar of .js .jsx .ts .tsx, HTML, package.json

Maps the modules, imports, entry points, preload and IPC bridges, and network endpoints an app uses.

Built in. Works on a folder or an .asar, not a single loose file.

Source maps

Desktop tool

.map (with its built script)

Ties minified code back to the original file names and line numbers.

Built in.

Mac & iPhone app structure

Desktop tool

.app, .ipa, Mach-O programs and .dylib

Bundle anatomy — helpers, frameworks, entitlements — plus load commands, signatures, and Objective-C / Swift metadata.

Built in. Some detail (slices, asset catalogs) needs a Mac. Disassembly needs a provider below.

XZ & 7-Zip archives

Desktop tool

.xz · .tar.xz · .txz · .7z

Lists, hashes, and unpacks the files inside. Encrypted 7-Zip headers are reported; no password is ever tried.

Needs the xz program or libarchive's bsdtar installed. The web library recognizes these files but does not unpack them yet.

Apple UI resources

Desktop tool

.nib · .storyboardc · keyed-archive plists · .plist · Assets.car

Reads the interface objects, their outlets and actions, archived object graphs, and asset metadata.

Built in. Asset catalogs and some plists need a Mac.

.NET assemblies

Desktop tool

managed .exe and .dll (up to 128 MiB)

Types, method signatures, CIL instructions, the native P/Invoke boundary, and differences between two builds.

Built in. Decompiled C# is optional with ILSpy. No single-file or IL2CPP bundles.

EVM bytecode

Desktop tool

raw or hex contract bytecode (up to 4 MiB)

Recovers the likely function selectors, their arguments, and whether each changes state.

Built in. Newer EOF containers aren't supported yet.

Network captures (HAR)

Desktop tool

.har

Reads the recorded requests and responses from a saved browser session.

Built in.

With a provider you bring

Taking a compiled program all the way down to readable code needs a specialist tool you install yourself. Oopsware drives it and brings the results into one place; it never installs these for you.

Native binaries, deeply

Provider

ELF, PE (.exe/.dll), Mach-O, 16-bit DOS programs

Disassembly and decompiled, readable pseudo-code for the functions inside a compiled program.

Bring Hopper, Ghidra, or IDA. Some targets are limited to one of them, and a few steps need a matching operating system.

Android apps, deeply

Provider

.apk

The manifest, classes, decompiled Java, and decoded resources and strings.

Bring jadx, apktool, or JEB. Split APKs and app bundles aren't covered yet.

A connected Android device

Provider

USB, emulator, or network devices

Device, package, and display facts, logcat, and pulling or pushing files and apps.

Bring adb (the Android platform tools).

Firmware images

Provider

raw firmware images

Finds the regions inside and carves out embedded filesystems and blobs.

Bring binwalk or unblob. Verified on Linux.

Live web pages

Provider

open tabs and URLs

The page's structure, scripts, network, storage, and screenshots, including scripted walkthroughs.

Use your own Chrome-family browser.

Running programs

Provider

Node/Electron inspectors, terminal commands, Mac app windows

Watches a program while it runs: scripts it loads, pages it shows, and call traces.

Built in on Linux/macOS; the Mac window and call-trace parts need a Mac.

Obfuscated JS bundles

Provider

a single minified .js bundle

Turns one packed, minified bundle back into readable modules.

Bring Wakaru. Verified on Linux.

Proxy captures

Provider

mitmproxy flow files

Reads the requests and responses recorded by a proxy.

Bring mitmproxy. Linux only.

Everyday files

The library is useful for ordinary files too, not only reverse-engineering targets. Here is what the browser does with the common ones today.

Documents

In your browser

.pdf · .docx · .xlsx · .pptx · .txt · .md

Markdown and text get the structured reader; PDF and office files are identified with a text, hex, and strings view. Deep document parsing is on the way.

Images

In your browser

.png · .jpg · .webp · .heic · .svg · .gif

Identified by their bytes with size and SHA-256; the raw bytes and any text inside are viewable.

Audio & video

In your browser

.mp3 · .m4a · .wav · .mp4 · .mov · .mkv

Identified and hashed; the container bytes are viewable and the file is downloadable.

Code & scripts

In your browser

.py · .js · .ts · .sh · .ps1 · .html · .css

Readable as text right away; the desktop tool maps whole JavaScript apps.

Data & config

In your browser

.json · .jsonl · .yaml · .xml · .toml · .csv · .tsv

Read with a format-aware structure view: every value with its place in the file, problems with exact positions, and nothing fetched or run.

Databases

In your browser

.db · .sqlite · .sqlite3 · .sql

Identified and previewable today; browsing tables and running read-only queries is coming.

Archives

In your browser

.zip · .tar · .tar.gz · .gz (unpacked) · .xz · .7z (desktop) · .rar (coming)

Zip, tar, and gzip are unpacked and browsable now; xz and 7-Zip unpack in the desktop tool; RAR is recognized only.

Installers & apps

In your browser

.apk · .ipa · .msix (unpacked) · .exe · .dmg · .pkg

App packages are unpacked; plain installers are identified and previewable.

3D & CAD

In your browser

.stl · .step · .dwg · .obj

Identified by their bytes with a raw view; the original downloads intact.

AI model files

In your browser

.gguf · .safetensors · .onnx

Identified and hashed, with a header and strings view; downloadable in full.

Oopsware separates what it observed from what it could not. A file being listed here means the library can read it to the level shown — never that it ran the file or judged it safe.
